## Canonical state model — target contracts, not implemented schemas

Use small named records with specific writers; no universal state/ability/transaction engine. Proposed service names express responsibilities and do not require new files when existing modules can own them.

Every confirmed read model carries `{schema, epoch, cityRef, factsVersion, validity, availability}`. `cityRef` is current owner/id/position/identity-generation evidence, NOT permanent identity. `cityKey` is a future stable city identity across transfers; derive neither from owner:cityID alone nor location alone (razing/refounding). Existing DEV binding tokens are accepted only in their verified original scope until a separately tested migration maps them. Unknown old history remains unknown.

Former entries use independent historical state and are labelled history, no ordinary-building rows/types, no ACTIVE source effect. Each stage tooltip owns its RP and newly unlocked ability packages; inactive ability text/reason can differ while institution stays. No extra16 facade buildings.

Unknown catalog universe is not a false total denominator; unknown domestic state is not “none”. Confirmed move/trade invalidates both endpoints and relevant index consumers. Hover zero requests; no automation.

Commerce production-list action entry has distinct tagged action identity, intercepts BEFORE native production request, never enqueue/finish/restore. Toggle request includes desired state, cityRef, expected config/input revision and action nonce; Gameplay validates capacity and persists order, returns authoritative result. Capital/development open once → combined versioned quote set → local panel selections → single confirm; confirmation revalidates current facts/funds and rejects stale quote rather than silently charging changed terms. Do not expose locked outcome/pity in public ExposedMembers presentation table. Restructuring reuses map preview/confirm style, but its persistent asset state is independent of unit, unlike ephemeral Crew preview.
