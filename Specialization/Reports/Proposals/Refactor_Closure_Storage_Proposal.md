## 建议的新规则：仅面向后续批次

1. **Git 留简报：**批次／证据等级、受测源码快照定位、命令与必要环境、结果数量、开放反例、关键前后测量、新增失败及限制。不要逐批复制完整继承矩阵。
2. **完整工件留本地：**写入被忽略的 `local/`，简报记相对位置、SHA256 和重跑前提；不默认提交。需要长期独立保存的原始失败或特殊实测证据单独识别。
3. **只保存有意义的增量：**重复通过项用版本、选择集和完整工件指纹定位；独有失败、修正理由及关键 producer/consumer 组合证据留下。摘要不替代真实验证，不降低测试断言。
4. **不宣称精确再生：**重跑可以产生可比较结果，不能恢复过去运行的原始字节。当前 dirty HEAD、外部数据库和环境记录不足以支持该承诺；哈希也不能恢复丢失工件。仅存本地的新完整工件没有跨机器永久保存保证，简报必须明示。

## 现有 Closure 能否安全移除？

**可以有条件地从当前分支文件树移除；不能现在直接删，也不建议从 Git 历史彻底清除。**

- 已逐份核对：31／31 当前文件与本地 `origin/develop` 引用中的字节相同，均可从已推送提交取回。原始证据可依靠历史提交保留，而非靠将来重跑替代。
- 若另行批准清理：先新增简短历史索引，逐份记录原路径、保存提交、SHA256 和取回方式；保留独有基线／失败结论。然后用普通新提交移除当前树中的 JSON，并配套调整**当前** Context Lock 与导航；不改历史提交、旧结果正文或原始字节。
- 冻结 Markdown 的旧相对链接会因移除而失效，须由新索引提供明确历史入口，不能假装旧链接仍有效。清理前验证每份原件能按提交取回并通过哈希检查，且现行锁／引用检查通过。
- 这种清理可减少当前文件树和最终 PR 约 **212,720 行新增**，但**不会回收 Git 历史体积或保证 clone 变小**。彻底瘦身涉及历史重写，另需独立决策，本次不建议。
