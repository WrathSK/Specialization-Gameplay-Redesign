# Network后台数据来源：用户澄清与实施决定

Document Owner: Codex
Decision State: USER_CONFIRMED
Design Basis: D0008 / NET-004（玩法不变）

用户明确：早期UI限制是不接受玩家先打开某个窗口才能读取；接受后台读取UI可用的正常数据，BTS数据可按可靠来源推进。此前Codex将其扩展为“必须纯Gameplay来源、不得接受UI快照”属于过度限制，现在撤销该前置条件，不再索取桥接方向批准。

采用独立后台脚本读取BTS/原版使用的当前Outgoing数据，并桥接Gameplay重建连接与分发。无需打开、隐藏打开或自动操作任何窗口；不强制依赖可见BTS实例已初始化的缓存。现有B007–B009后台探针的成功证据可复用；文件夹与API执行上下文仍准确标注，不把UI来源改名为Gameplay原生来源。

用户认可BTS数据可靠，故不重复发起其数据显示正确性的验证争议。仍需验证的是本Mod自己的工程链路：自动初始化/读档就绪、完整批次传递、顺序与去重、路线取消/掠夺后的及时更新、参与玩家覆盖。可靠上游不能自动证明新写的桥接代码通过；本条用户授权不是新增实机PASS，也不立即启动网络收益。

下一实施顺序：适配明确的BACKGROUND_UI_CURRENT来源契约（暂定内部标签），保留完整性校验和已知来源；完整批次交接后重建源→中心→接收城市集合，再核对变化/撤销。角色ACTIVE变化也重算派生结果。读取失败不把历史事件当当前路线；不要求Gameplay重复证明已读端点，但可保留低成本当前城市/商人校验作为诊断。

无需更改D0008商路方向、真实带宽、全网络分发、接收城市去重和多源规则。显式连接槽位方案暂不推进；只有后台方案实际无法满足机制时再讨论玩法替代。纯Gameplay隐藏接口研究变成可选优化，不再阻塞主线。旧TradeRouteState.lua仍只允许GAMEPLAY_CURRENT，是下一步要改的实现限制，不能通过改标签绕过；运行UI_SHADOW_ONLY当前尚未接正式网络，验证状态不随文档授权自动升级。

本轮仅同步协作/架构/状态/提案，运行仍B024/31，Source/Tests/Design未改，不启动游戏，不派新测试。
