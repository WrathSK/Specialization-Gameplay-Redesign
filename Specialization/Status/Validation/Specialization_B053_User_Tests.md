# B053 购买货币实验

Document Owner: Codex
Status: USER_GAME_TEST_REQUIRED
Build: P0-B-053 / modinfo69
Design: D0016

完全退出游戏再启动，加载原测试存档即可。选择一座未建纪念碑或粮仓的己方测试城，没有合适城市时用Cheat新建一城。不要求工业专业或商路。本批是手动实验，不是正式网络折扣。请使用单独测试存档，不实际购买建筑。

## 1. BASE对照

点击Purchase BASE：临时允许本城市中心建筑Faith购买，20%折扣关闭。关闭P0窗口，分别查看金币/信仰购买页中的同一目标（纪念碑或粮仓），记G0/F0；再Read purchase可直接显示两种getter价格。要求两种购买页均确有目标；否则属于测试条件未成立，回传报告，不把不可购买时getter的假设价格当PASS。

## 2. ON及重复

点击Purchase -20% ON，重新打开两种购买页，记G1/F1；再点ON，价格不能继续下降。没有其它折扣时Gold应约为G0×0.8，考虑引擎整数/取整。Faith保持F0表示可隔离；Faith也约为F0×0.8表示双币折扣，D0016已允许其作为隔离困难时的方案，不属于设计拒绝。Gold完全不变/涨价、连续点击叠加均为FAIL。存在其它购买折扣时不要自行按0.8断言失败，回传原始值以分析叠加层级。

## 3. OFF恢复

点击Purchase OFF：Gold应回到G0；临时Faith购买条件撤销，若原本不能Faith买则项目应从Faith页消失。再次BASE应恢复G0/F0，证明Faith折扣也已撤销；最后OFF结束。保存后重载也会自动清除实验，不保留ON测试状态。

如果刚点击价格尚未更新，关闭再打开购买页并Read purchase；仍不变可过一回合，分别记录是否延迟。任一按钮报B053_DATABASE_MISSING先回传，不急于新建局。

回传最少：G0/F0→G1/F1，重复ON是否稳定，OFF是否恢复。报告截图可代替抄数，若getter与购买页不同则各一张；错误时附Lua.log的[SPC][B053]及Database.log错误段。不需要完整DB。尚无自动标准化折扣，不测试网络撤销。
