## Change and ownership

The [Gameplay Gate](../../../../Mod/ExpeditionSpyGate.lua) publishes a small transition-only activity view for the exact session team. TASK becomes TASK_PREPARING. The independent two-player-turn fixture timer starts only after the UI acknowledges observed native SLEEP. Neither the timer nor the acknowledgement executes Gain Sources or a native Spy mission.

A separate invisible [activity addin](../../../../Mod/UI/ExpeditionSpyActivity.lua) stays available when the management window closes. It checks local supported owner, exact current Unit ID/type/raw name/position and native operation -1. It requests native SLEEP once, reads back the activity, and later requests WAKE once only for sleep owned by this task. An already-sleeping unit is accepted without claiming its sleep; completion leaves that pre-existing activity alone. Release readback accepts AWAKE/HOLD. Unknown identity, native mission, unsupported API/permission or timeout stops instead of bypassing guards or retrying commands.

Pending readback polls at 0.25s for at most10s per transition. No idle per-frame poll, collection scan, native mission cancellation, end-turn bypass or new Property/ledger/schema. ASLEEP checks use an available UnitActivityChanged event and local-player-turn entry, reading only the exact unit. If that optional event is unavailable, same-turn external wake detection is not guaranteed; normal task controls remain isolated and the next local-turn check remains. Native event ordering, SLEEP/WAKE eligibility and needs-orders suppression are not established by mocks.

The bounded activity lease retains an attempted sleep across delayed acknowledgement, source loss and cancellation; cancellation releases only the attempted sleep, not pre-existing sleep. A late sleep sample stops without starting the timer and retains release responsibility. Release failure becomes BLOCKED without repeated writes. If a sleep request was attempted but SLEEP was never observed, an awake/hold reading does not prove the pending request can no longer arrive: cancellation becomes ACTIVITY_SLEEP_OUTCOME_UNKNOWN and retains the prototype for explicit END instead of claiming cleanup. Source validity is required to start/advance the task; releasing our unit activity does not require a still-valid source city. Exact unit/name/position/native-operation checks remain mandatory. Separate bounded activity/window reply slots prevent an asynchronous acknowledgement from consuming the management window's response. No unbounded reply registry.

The [UnitPanel wrapper](../../../../Mod/UI/ExpeditionSpyUnitPanel.lua) retains management, suppresses Skip during preparation/task/release, and rechecks cached callbacks. Existing exact-type native wake/mission/dispatch redirection remains; ordinary Spies and other units use their native path. Transition refresh rebuilds only the selected custom unit's actions. [Window](../../../../Mod/UI/ExpeditionSpyWindow.lua) uses a matched current activity view instead of stale diagnostic replies, shows concise preparation/running/release/error text and keeps exact END available. New localized keys under LOC_SPC_EXPEDITION_SPY_: PHASE_TASK_PREPARING, ACTIVITY_SLEEP/ASLEEP/RELEASE/NONE/BLOCKED/ERROR/WAIT (Chinese and English).

Own capacity1, exact original city source, native name arrival continuity, temporarily accepted native Spy-slot cost and independent no-reward completion remain. TASK_COMPLETE is still a one-task fixture; this patch does not enable repeated dispatch/task cycles. Closing the panel does not cancel the activity bridge. Cold loading cannot reconstruct a session task or adopt saved sleep by name; the existing explicit END of the surviving prototype is the recovery path. Formal N1 persistence/reattachment and N2/N3/U2/rewards stay held. Design, GC, ordinary Spy definitions and external mods unchanged.
