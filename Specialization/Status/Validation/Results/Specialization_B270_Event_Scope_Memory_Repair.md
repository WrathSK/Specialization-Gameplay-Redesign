## 调查结论与修复边界

事件驱动只限定何时工作，不自动限定一次事件要检查多少对象。旧consumer将若干区域/改良/建造事件当成全世界核对入口；已经退休的载体也在普通Audit反复检查。因此，在尚未建立专业的早期，AI建设事件仍会产生大量Lua分配和原生读取。它们是已证实的多余工作；尚不能据此认定进程内存增长全部由此造成。

最新交付会话有两段Gameplay加载：TRAIN 1–893、内存记录1–26及1–78连续。第二段T28 END→T53 END增加421,806次城市访问、10,402,464次建筑检查；其中95.93%城市访问、90.45%建筑检查发生于本地END至下一BEGIN之间。最新T54 BEGIN累计459,975/11,509,999，旧摘要只显示T53 END的432,349/10,838,595。本批不改写冻结原始日志。

### 1. 证据质量与摘要

- Gameplay保存heapRawKB与heapStatus；不可用、异常、非数值、非有限数、负数分别记录。一次原生负值使当前Gameplay观察上下文的后续低正数保持RANGE_UNTRUSTED；不补算4GiB、不把它当GC成功，不据失真读数强行回收。
- 当前Mac ARM64游戏二进制的Lua计数路径读取低32位字节并作有符号换算，存在约2GiB负值及4GiB回绕。二进制SHA256为8eaba5fe819f81fbe642da39475cba4713e76f9ca68779fa9f68109043988c90。此为实际原生代码静态证据，不是仅从标准Lua推测。旧记录1865MiB→UNKNOWN→56MiB与该机制相容；旧版未保存异常原值，不能还原真实4.xGiB或断言每个UNKNOWN皆因回绕。全正数、未捕获负区间也不能排除回绕。
- 旧运行包没有新状态字段时固定查询标LEGACY，仍可读；不是把历史数据升级成新证据。摘要一旦观察失真区间，不被之后正值“洗白”。
- 进程读数仅在确认Tuner监听的连接窗口采样；断线退出尾部不进入正常游玩首尾差。最新旧会话连接期footprint约11.80→18.85GB，断线后约0.92GB曾使首尾摘要误呈负增长。加载/卸载过渡仍可能出现在连接窗口，摘要明确范围；PID/启动身份、30秒节奏、容量上限、失败停止保留。
- 最新工作量单独保留BEGIN/END/LOAD的turn和phase；逐END差值保持原含义，不漏掉最新BEGIN。

### 2. 有界GC补评估

原128MiB增长、2回合间隔、请求/Claim/模块/UI/路线/网络忙碌门禁及2秒失败锁不变。旧逻辑在UI发送侧inflight仍为1时消耗本回合唯一机会；Gameplay的NETWORK_VERIFIED不等于UI已退休发送标志。第二加载段T30–54均出现NETWORK_INFLIGHT跳过，不构成永久网络卡死证明。

本批仅让这一个跳过原因保留待办：发布通知先做标量inflight等待；归零后的后续Publish最多补评估一次，重走全部门禁。等待期间不读堆、不记重复日志、不回收。其它忙碌原因仍不循环重试；外国回合、本地结束、关闭/失败、回合变化取消。重复本地activation不能增加预算；不在ACK处理栈直接GC，不新增timer/逐帧检查。
