## Boost：用户提出的合并/分开取整假设

只做现有数据算术比较，不修改实现，不开启额外精度调查。设C为截图成本，e为面板额外百分点：

A = floor(C×(34+e)/100)
B = floor(C×34/100) + floor(C×e/100)

用Decimal精确十进制处理，避免Python二进制浮点偶然把本应整数的结果减1。

| 目标 | A合并后向下取整 | B两项分别向下取整 | 实测 |
|---|---:|---:|---:|
| 封建主义 | 273 | 273 | 269 |
| 砌砖 | 28 | 27 | 27 |
| 历史记录 | 115 | 115 | 114 |
| 扶壁 | 222 | 222 | 221 |
| 拱券 | 242 | 242 | 239 |
| 人文主义 | 512 | 511 | 498 |

砌砖：floor27.2 + floor0.88 =27，分开取整吻合。人文主义：floor489.6 + floor22.401142… =511，仍比实测498多13。对同一成本/同两项金额，合并floor与分开floor最多相差1，不能单独解释这类较大差距。额外百分点先floor再分别计算也不能统一解释（人文主义503而非498）。普通四舍五入的合并/分开版本也不统一匹配：依表顺序均274/28/116/223/242/512。

结论：用户的候选机制合理，部分数字支持，但不是已确认完整引擎公式。支持源升级/降级效果存在的既有证据不撤销；精确数值合同仍USER_GAME_TEST_REQUIRED。不因本次假设擅自补差、改系数或认定所有误差都是用户已接受的小数截断。
