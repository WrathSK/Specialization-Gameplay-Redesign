# B039：施工队注入前置（四个小案）

Document Owner: Codex
State: USER_GAME_TEST_REQUIRED

沿用测试存档，回主菜单重新加载，确认B039。无新SQL/单位，不要求新局。当前按钮Preview construction / Inject 250 (DEV)是免费生产力测试，不消耗移民或施工队。

每案统一操作：选己方城市→设置当前目标→点Preview construction截图（自动显示成本、进度、apply/discard）→点Inject 250 (DEV)→观察报告和原生队列。只剩一个目标时完成后EMPTY_QUEUE是正常的后状态，不是拒绝此次注入。调用前EMPTY_QUEUE则应拒绝。

1. **Building**：选一个尚需超过250生产力的普通建筑（有合适现存目标就用，不必重新开城），预期进度增加250且不跳到下项。若只能选剩余较少的建筑，则预期只增加剩余量并完成，报告会给出discard。
2. **District**：放置尚未完成的区域，预期增加min(250,剩余)；完成与否按预览明确数值。不要用Cheat“完成当前项目”代替注入。
3. **Wonder**：当前建造奇观，预期同样增加min(250,剩余)。观察是否被生产倍率额外放大/缩小或未生效。
4. **Overflow waste**：用剩余不足250的建筑/区域/奇观，后面排一个确认从未投入、进度0的目标。注入后首项完成，超额discard，后项进度仍0。再点一次Inject应提示先Preview，不能再增加生产力。该案可与前面已有目标衔接，四个判据不要求四座城。

PASS：原生进度/完成符合预览，后项0，重复注入不发放。FAIL：目标不支持、进度超出/低于预览、超额进入后项、重复发放或RESULT_UNCERTAIN。若只是界面滞后可重选城市核对，并说明先后；不要在不确定后反复Preview+Inject。

正常可口述前后数值，异常附预览和注入后报告截图；overflow优先保留下一项0进度证据。错误附Lua.log。尚不测试Crew消耗/项目成本，原正式四案中消费单位部分延后。
