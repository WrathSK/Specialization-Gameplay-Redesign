# B051：自动复制收益（三项）

Document Owner: Codex
Build: P0-B-051 / modinfo65
Status: USER_GAME_TEST_REQUIRED（需要用户在Civ VI实机验证）

## 共用准备

退出至主菜单后重新加载现有测试存档即可先试，不强制新开。面板应显示B051。若提示B051_DATABASE_MISSING，请保留Database.log/Modding.log；旧存档的新数据库效果尚需此次确认，不以“已配置”当实测通过。

曾做B050的城市先点击Half OFF，避免额外0.5混入。正式两项现在自动生效，不要Half ON。沿用已有四类专业区域与商路；不重复验证起终点/分页。状态改变后留约2秒供后台采样，再用Read Lv4 copy记录。关闭P0/贸易面板同样应生效。该按钮本身不会触发收益刷新。

每项比较条件尽量固定：人口、工作专家、政策、宜居度及其它加成。若面板仍旧值，可过一回合并记录这个事实；已接受的显示延迟不等于本项错误。原生总量可能有1/256左右量化，避免只比较右下角四舍五入整数。

## 1. 科研城本地复制及撤销

使用已有潜力4科研城，城内另有已完成工业区/剧院/商业中心，最好能使“非学院标准区域合计”是奇数以验证半点。暂将Campus工作专家调到0，并维持0，避免科研III和IV专家奖励一起改变。无需拆建区域。

1. 总督调离、ACTIVE回落后读取：本项SCIENCE预期/已配置应0，记录原生Science总量及宜居度。
2. 原高等级总督返回并建立、ACTIVE4后读取：SCIENCE预期=非学院标准区域合计×50%，已配置应相等。记录原生Science总量。期间人口与宜居度变化时，不直接用两次城市总量作差；报告这些变化即可。
3. 保持状态、关闭面板等几秒，再读取一次：配置、区域基数及原生总量不应因后台重复处理持续增长。然后调离总督，配置应回0；固定其余条件下总科技应撤销对应收益。

PASS：正常条件下真实科技增加/回落，与本项配置经过本城原生百分比后的变化一致；整数/半点不丢失；后台重复不累加。−1宜居度的0.5基础部分最终约0.45是正常倍率现象。若不方便手算，回传前后报告与城市产出明细、宜居度，由Codex计算。
FAIL：配置正确但无实际收益、额外累加、ACTIVE下降后仍保留本项收益（过回合亦不撤销）、半点明显被截去。未知区域/精度限制提示属于当前不支持场景，不当作通过。

## 2. 工业网络跨城发放、最高源与回退

沿用已有接收工业网络的城市和工业IV源。先在源城读取工业区Actual生产力，再在接收城Read Lv4 copy：PRODUCTION预期/已配置应为报告当前最高源50%。维持接收城人口/专家/宜居度。

1. 把最高来源总督调离：接收城配置回退到剩余ACTIVE4来源的最高值；没有其它IV来源则为0。记录接收城原生Production前后值。
2. 恢复来源总督建立：配置与实际收益恢复。关闭面板等几秒后重读一次，不应不断增长。

已有第二来源则同时检验max而非sum；没有第二来源不要求额外造城，先验单源→0，max多源仍记录未实机。比较接收城时，尽量选没有自己的工业区、无其它本轮效果变动的城市，避免源本城产出变化混入。

PASS：真实接收生产力随配置回退/恢复；有多源时取最大金额、不相加；来源区基数不被接收奖励反向抬高。FAIL：总督撤销后旧量保留、累加、城市层奖励回流导致源基数不断增长、已配置非0而原生始终无变化。

## 3. 保存读档与人口变化

沿用上述已生效城市，选择至少一项复制目标以.5结尾的城市。保存，重新加载；不要先打开P0或贸易面板，先观察城市普通产出，再Read Lv4 copy。预期/已配置应恢复原值，不能重复奖励。

随后只增加该城人口1（Cheat即可），保持区域产出/来源与ACTIVE不变，等后台刷新再读。复制“已配置”仍是原先固定金额；不能随着人口多出0.5。人口本身会影响城市基础科技/生产，因此不要求两个人口阶段的原生总量相等；回传两阶段报告与产出明细即可。过回合后再观察没有持续增长。

PASS：不开专门面板也恢复；读档前后相同条件收益相同；半点在新人口下仍正确且无重复。FAIL：必须点击读取才能恢复、读档翻倍或丢失、人口改变后固定补贴随人口膨胀。若只能用整数金额，人口半点子项记未测，不扩大PASS。
